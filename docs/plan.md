## Stack and layout

```

                      edit commands, bundle builders, export range and target model constraints
```

## The guide bundle (contract with model-arena)

`model-arena/packages/core` owns the JSON Schema. This repo validates against a pinned copy, `schema/guide-bundle.schema.json` (version 0.1.0 written here from this table on 10 November 2026; 0.2.0 on 11 November adds the optional camera track). **To do:** re-sync `model-arena`'s schema with 0.2.0.

| Field | Meaning |
| --- | --- |
| `video` | MP4, H.264, 24 fps, frame count 8k+1; 1280×720 by default |
| `audio` | the track, trimmed to the exported range |
| `firstFrame` | PNG of frame 0 of the export; optional `firstFrameStyled` |
| `beats` | beat and downbeat times and BPM, re-based so times count from the export's frame 0 |
| `recipe` | the recipe that produced it (whole recipe, not trimmed) |
| `meta` | width, height, fps, frames, view, character, generator, licence per asset, `audioInVideo` |
| `camera` | optional (0.2.0): `camera.json`, per-frame position, target and vertical fov of the camera rig, with a suggested LTX `cameraMovement` (approximate) |

The bundle also carries `bundle.json`, a manifest naming each file. **Schema gap:** the schema has no field for the exported section of the recipe, so a mid-track range is written into the video asset's `name` ("Rendered guide, recipe frames 107-211 (4.458-8.833 s)"). Proposal for the next schema version: `meta.range { startFrame, startSeconds }`.

**Target model constraints** (700–4553 px per side, 24–60 fps, 3–30 s) sit in one small table in `packages/core/src/export-target.ts`. The sibling repo `model-arena` holds the full per-model spec database; re-sync the table with it.

## State, 10 November 2026

Branch `feat/ms-core`. Three levels of evidence:

**Built and browser-verified** (`npm run smoke`: real headless Chrome, synthetic fixtures, ffprobe):
- loading a WAV track; BPM and first-beat detection (112.1 BPM, 0.20 s on a 112 BPM click track);
- placing library moves on beats from the palette; the five views render (screenshots);
- export at the 1280×720 default; a mid-track range (beats 8–16 of 20): 105 frames, H.264 1280×720 at 24 fps, AAC muxed, `audio.wav` trimmed so its first click lands on the first beat of the re-based `beats.json`;
- the inline size warning (832×480) and clip-length warning (under 3 s), neither blocking the export;
- portrait framing (720×1280) keeps outstretched arms in frame (screenshot, checked by eye);
- loading a generated skinned GLB with three embedded clips; Mixamo bone names recognised; clips sequenced on beats and exported;
- the inline confirm on switching to the loaded character: *Keep* leaves the library moves, *Clear* removes them; no browser dialog appears.

**Unit-test-only** (`npm test`, 46 tests):
- recipe validation and round trip; engine determinism and phase timing on the beat grid; pose speed classes;
- the edit commands `insertMove`, `swapMove`, `removeMove`, `setAmplitude`, `extendPhase`, `applyMotionCommand` (the UI calls them, but the smoke run drives only `insertMove`);
- beat analysis on synthetic click tracks; bundle JSON against the pinned schema; WAV encoding;
- export range resolution and 8k+1 snapping; target constraint warnings; move compatibility on a character switch.

**Built, not verified by any automated run:** FBX loading; drag and drop; audio playback; editing a selected move (amplitude, fps, blend, expression, swap, remove); applying recipe JSON by hand; the block figure; the dark background; exporting at 1920×1080 or 720×1280; custom sizes above 1920×1080 (H.264 level 5.1 is tried, untested).

**MS-9a, audio-reactive camera and motion (11 November, verified by `npm test` 68 tests, `npm run smoke`, `npm run examples`):**
- Camera rig (`camera.ts`, `camera-rig.ts`): modes static, orbit, push in, pull out, rise and tilt, lead (front of the subject), chase (behind), in a timeline per beat range. Orbit, dolly and crane speed follow the smoothed energy; every beat gets a push and a yaw nudge, downbeats a larger one, peaking on the beat. Rates are slew-limited, followers are critically damped with feed-forward, accent amplitudes are cut until their peak acceleration fits the clamp. Unit-tested: determinism, envelope, accents within one frame of the beat, acceleration clamps, chase framing.
- Audio drive (`audio-drive.ts`): per-frame energy (95th-percentile normalised, 0.12 s attack, 0.5 s release) and onsets (adaptive threshold, within one hop, about 12 ms).
- Reactive motion layer (`reactive.ts`, `accents.ts`, `perform.ts`) on top of the time-stretch path: per-bar tempo levels from energy (idle, half, normal, double, cross-faded at the bar), amplitude by energy, accent moves (hit, point, strike, kick, jump, spin) on onsets and downbeats with the key pose landing on the hit (a jump lands on it), per-joint lag for overlapping action and follow-through, seeded variation. Editable hit markers (`reactive.markers`) replace detection when present. Unit-tested: accents within one frame of onsets and downbeats, jump landing, same seed same output, different seeds differ, repeats differ, quiet bars idle, arms trail the hips.
- Studio: a Camera rig view; rig and reactive-moves controls; the top and orbit views draw the camera path, frustums at downbeat accents, a live frustum and the dotted floor path (hidden in exports). The fixed views stay switchable whatever the rig does. Browser-verified by screenshot (`npm run peek`, `npm run examples`).
- Export: `camera.json` (per-frame position, target, vertical fov, energy; the mode timeline; accents; a suggested LTX `settings.cameraMovement`, marked approximate). Values are the LTX list in `model-arena` (`providers/runware-api/models.ts`): dolly in, out, left, right, jib up, down, static, focus shift. Verified by `npm run examples`: A, C, D export with a camera track whose frame count matches ffprobe.
- Examples: `examples/recipes/{A,C,D}.json`; `npm run examples` regenerates the 48-beat track and the bundles in `examples/bundles/` (gitignored). D is the target form: the dancer and the camera follow the same beats.
- **Schema:** the pinned copy is now 0.2.0 (optional manifest `camera`, `$defs/camera`, asset role `camera`). **`model-arena`'s schema must be re-synced** before it reads these bundles; a 0.1.0 reader rejects the extra manifest key.

**Gaps:**
- Library moves do not drive a loaded rig: recipe poses need rest-pose retargeting onto the file's skeleton. A loaded character plays only its own embedded clips; the switch confirm offers to clear the library moves.
- No IK and no foot locking: feet can slide or sink slightly during blends; the bounce pose is solved by hand so the feet stay put.
- The `expression` field is validated, stored and exported, not rendered.
- MS-3 is a simple beat strip; there is no phase-block timeline, speed curve or before/after comparison yet.
- No CLI or MCP yet; the commands are a library.
- The range is not previewed: playback runs over the whole recipe.

### MS-9c, rigged mannequin and the audio clock (11 November)

Built (verified by `npm test` 86 tests, `npm run smoke`, `npm run examples`, `npm run peek` screenshots):
- The bundled rigged mannequin (Ecctrl AnimationLibrary, MIT; animations CC0, see `assets/characters/NOTICE.md`) is the default character; the procedural mannequin is the fallback.
- Clip performance (`clip-library.ts`, `clip-perform.ts`): loops time-warped so steps land on beats; accent clips as phases placed on the audio clock, the key frame (landing, impact) on the hit; amplitude per step or from energy; a hand-edited energy curve; retimed phases stored per marker.
- Energy drive: `reactive.drive` (default 1) scales how strongly energy sets playback (tempo level per bar, snappier steps when loud) and amplitude (bigger, heavier when loud, softer towards idle when quiet). Tested on the real clips: Dance_Loop at energy 0.9 against 0.2 shows about 8 times the pose speed, 1.6 times the knee range and 2.4 times the arm range.
- Timeline lanes (phases, moves, amplitude per step, a 230 px energy graph with pencil, point handles, snap to steps and a value readout; markers draggable), transport rate and preview fps, a drawn camera path, bones, x-ray, onion skin, arcs, the move gizmo, and a Mixamo-to-DEF retarget module (bone map and synthetic test).

Built from Radek's feedback (11 November, branch `feat/ms-core`; `npm test` 119 tests, `npm run smoke`, `npm run examples`, `npm run mixamo-check`):
1. **Smooth transitions** (`packages/core/src/transitions.ts`): eased crossfades between moves, never under 6 frames; a gait following a gait starts on the matching foot; accents fade in and out over at least 6 frames, a clip switch inside an accent crossfades over 8 frames, a later accent covers an earlier one. The blend per transition is a handle on the move lane (frames, 6–24) and a field in the inspector. Tested on the real mannequin: no joint pop above 30 degrees per frame across move changes, gait changes and back-to-back fight accents (the old code popped 88 degrees).
2. **Delete and undo**: Delete (close the gap) and Shift-Delete (hold), and a right-click menu, for moves, accent phase blocks, markers and steps (`packages/core/src/delete-edits.ts`; markers gain `skip` and `hold`). Undo and redo (Cmd-Z, Shift-Cmd-Z) for every recipe edit; one pointer press is one undo step. `app.ts` was split first (`app-view.ts`, `export/button.ts`).
3. **Sequences**: Save, Save as, Load, Delete, download and upload of the recipe .json, a browser library plus the committed `examples/recipes/` (new: `fight-combo`, `gait-change`). Every committed recipe reloads to identical frames (test). Fields documented in [recipe.md](recipe.md).
4. **Mixamo**: animation-only FBX/GLB clips are retargeted onto the rigged mannequin (drop, file picker, or `assets-local/mixamo/` in dev) and play as `mixamo/<name>`. `npm run mixamo-check` writes sheets, MP4s and metrics to `out/mixamo-check/`; verdicts in [friction.md](friction.md#mixamo-check-11-november-2026). Next: foot IK and travel speed per clip.

Then, also 11 November:
5. **Accent feel per marker**: "hit harder" (`impact`, 0–1: overshoot past the key pose, a deeper squash with the planted foot kept down, a hold of up to 3 frames on the impact frame) and the wind-up length (beats snapped to the step division, or frames; stored in `phases`), in a marker inspector and by Shift-dragging an accent's start edge in the phase lane.
6. **Per-bone sync for dance** (`reactive.sync`): additive layers on the mannequin, each with an amount: head nods on beats, shoulders and arms on onsets (the backbeat without a track), hips on the kick and bass (a new low-band envelope), with two-bone leg IK so the feet stay planted. Controls in the Reactive moves panel.

Known: `Sprint_Loop` at 120 BPM plays 1.33 times its authored speed and the loud-step snap adds a velocity kink at each step, so it reads jittery on its own (58 degrees per frame at its worst); a smoother snap curve is a small follow-up.

### MS-9b, after D (next, in this order)

1. **Floor paths and beat-timed jumps.** One character per clip travels an editable floor path (a few control points, a smooth spline); travel speed follows energy; accent moves on the hits along the way (a jump that takes off and lands on the beat, a strike, a spin). Accent sets stay data, so a ninja combo or skateboard tricks are new entries.
2. **Waveform timeline.** Under the viewport: the waveform with the energy curve over it, and the hit markers (onsets and downbeats) drawn on it. Markers are editable (drag to move, click to add, delete, pick the accent per marker) and write `reactive.markers`; the playhead follows the viewport.
3. **Audio mapping controls.** Marker detection threshold, energy smoothing (attack and release), the energy-to-speed and energy-to-amplitude amounts, and a time offset to nudge everything a few milliseconds earlier or later.
4. **Blockout room.** An optional greybox scene (floor with a faint grid, a few walls, a ramp, pillars, flat neutral colours) for the floor-path and blocking examples; the lead and chase rigs work in it.
5. **Blocking mode and example B.** One to three figures on simple floor paths, translate and turn only, each in a distinct flat colour; example B pairs them with the reactive orbit and push-ins.
6. **Example E.** Audio-reactive running into ninja moves on the hits, in the room, with the lead or chase camera.

### MS-10, game and still outputs (after MS-9b)

- **Sprite sheets.** Render each move or gesture from fixed cameras (orthographic, 4 or 8 directions, and the isometric view) into a packed PNG grid plus JSON frame data; the same move also renders as film. Nothing blocks this: every frame is a pure function of (recipe, drive, frame) and the fixed views are plain cameras.
- **PNG frames** from the flat (orthographic) and isometric views.
- **SVG silhouettes:** trace the rendered silhouette per frame.
- **MotionBricks experiment** (the L3 spike, MS-7): generate in-between motion and travel speed from the hit markers, aimed at the robotic look. `reactive.markers` is the keyframe list it fills between.

### MS-7, MotionBricks (spike first; build only on a yes)

- **Spike:** two hours on an NVIDIA box. Does the early-preview code (GR00T-WholeBodyControl/motionbricks) run outside the robot stack? Which skeleton does it output, which input format does it take, does it accept SOMA, and what are the weight terms?
- **Generator:** `providers/motionbricks`. Beat keyframes in, clip out, retargeted in Three.js (`SkeletonUtils.retargetClip` or an Apache-licensed retargeter).
- **Serverless:** `serverless/motionbricks` as a custom container, with one batch endpoint per move set so a single cold start covers it.
- **Acceptance:** one agent-edited recipe rendered through MotionBricks, shown next to the time-stretch version.

### MS-8, pose input (after the first milestone)

- **2D:** DWPose or RTMPose (Apache), drawn in the OpenPose style.
- **3D:** GEM-X to SOMA, retargeted to Mixamo naming.
- **Two-stage route:** GEM-X keyframes go into the recipe and MotionBricks fills between them. Keyframe density is the fidelity dial.
- **Licence gate:** no SMPL, GVHMR, AIST++ or raw Mixamo files in the repo.
